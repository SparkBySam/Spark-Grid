# Spark Grid agent rulebook

This file is the source of truth for Cursor, Claude Code, and any other agent. If another instruction disagrees with this file, this file wins unless Sam wrote the other instruction in the current task.

## Start every session here

1. Read this file and `docs/STATUS.md`.
2. Read `.cursor/rules/performance.mdc` before any change to calculation, import, export, the document store, or the grid.
3. Pick the next task from the top of `docs/gaps.md` inside the current phase in `docs/STATUS.md`. Do not invent a side quest.
4. One change per commit. The subject is a task id and a one-line summary, for example `A.4: Calculate range precedents before reading them`. The body has the gate result, the answer-check count, and before/after Release timings for every affected path.
5. `scripts/ci.sh` must pass before every commit. It stops at the first failure. A failing gate is fixed. It is not skipped, commented out, or given a looser threshold. Changing a threshold needs Sam's approval. The latest result is in `docs/STATUS.md`.

## Non-negotiables

- People trust Spark Grid with their numbers. A crash loses their work. Crash safety outranks feature work.
- The KPI workbook is a benchmark, never a special case. Do not put one workbook's sheet names, addresses, column indexes, or formula shapes into engine or grid code. The check in `.cursor/rules/performance.mdc` must stay clean for new and changed code.
- A fast path that only fires on one file does not ship. A faster path that disagrees with the answer check does not ship. If a change is slower than the baseline, or the answer check gets worse, revert it.
- Do not upload a build, push to `main`, rewrite git history, delete user data, add a dependency, copy code from another project, change file-format compatibility, loosen a gate, or publish anything unless Sam has said yes in this task.
- Versions and build numbers stay where the project file has them unless the task says to change them.
- Each agent uses its own derived-data folder under `/tmp` and deletes that folder when the task is done. Do not delete the user's Xcode DerivedData.

## Never crash

SwiftLint enforces these rules on non-test code. The existing violations were removed in W4. Do not add more.

- No `force_unwrapping`, `force_try`, `force_cast`, or `implicitly_unwrapped_optional`.
- No `fatalError`, `preconditionFailure`, `precondition(`, `assert(`, or `unowned` outside tests.
- No `!` on dictionary or array lookups. Use a safe index helper.
- Treat numbers from files, formulas, pastes, and command parameters as hostile. Use checked or saturating arithmetic. Cap allocations sized by input: whole-column references, huge ranges, `REPT`, `SEQUENCE`, fill, and paste.
- Bound formula nesting, dependency-chain depth, and names that refer to names. Evaluation of a long chain must be iterative, not a recursive call per precedent.
- Swift traps cannot be caught. After an edit, the app writes a recovery copy of the open workbook in the background (`CrashRecoveryStore`, under Application Support). If the next launch finds that copy and no clean quit, it asks whether to restore it. Benchmark launches skip the prompt.
- Every crash fix lands with a regression test.

## Privacy and clean-room

- Never commit a customer workbook or anything derived from one: values, answer files, logs, or screenshots. The KPI file stays on the machine that owns it. Benchmark output goes to `/tmp` or a git-ignored folder.
- `scripts/answers/reference-answers.txt` is already tracked and is derived from the KPI file. That is debt. Do not add to it. Removing it is privacy work, not a drive-by delete inside an unrelated commit.
- The synthetic ledger answers are generated by `scripts/generate_ledger_workbook.py`. Those may stay. The ledger generator is not a customer file.
- `scripts/check-privacy.sh` looks at tracked paths (`git ls-files`), not `.build` checkouts. It fails on any `.xlsx`, `.xls`, `.csv`, or `.ods` outside `Fixtures/` (generated files only), any tracked file over 1 MB that is not listed in `scripts/privacy-allowlist.txt`, and anything under `scripts/answers/` except `scripts/answers/ledger-answers.txt`. The allowlist is empty. Adding a path needs Sam's approval. Customer files never go on it.
- Do not copy GPL, LGPL, or AGPL code, including LibreOffice and Gnumeric.
- MIT or Apache code is allowed only with its license notice kept and a row in `ATTRIBUTION.md`. `ATTRIBUTION.md` does not exist yet (W8).
- Do not ship Microsoft, Apple, or Google icons, templates, themes, fonts, or sample files. Feature and function names are fine.
- Every bundled image, font, or PDF under `Spark Grid/` or `Spark Grid Quick Look/` needs a row in `ATTRIBUTION.md` (author, source, license). `scripts/check-assets.sh` enforces that. It fails while the file is missing.

## Quality gates

`scripts/ci.sh` runs these stages in order and stops at the first failure. Each stage prints one summary line. The last line is `PASS` or `FAIL` plus the elapsed seconds. A stage may exit 10 to record a documented skip. A skip is not a pass of a check that should have run.

1. **Lint.** SwiftLint 0.65.1 in strict mode, config `.swiftlint.yml`. `scripts/lint.sh` downloads the official `portable_swiftlint.zip` and checks SHA-256 `c1e429b0599cf1b516f369a2d9ec04eaf0e436f3c12b637df8851fa52ff694d0`. The binary is cached in git-ignored `.tools/`. Rules are `force_unwrapping`, `force_try`, `force_cast`, `implicitly_unwrapped_optional`, and custom bans on `fatalError(`, `preconditionFailure(`, `precondition(`, `assert(`, `unowned`, and `]!`. `Packages/SparkGridCore/Tests` is excluded. SourceKit stays enabled, because this SwiftLint build skips custom rules when SourceKit is disabled.
2. **Format.** `xcrun swift-format lint -s -p` on every `.swift` file in `Packages/SparkGridCore`, `Spark Grid`, and `Spark Grid Quick Look`. `-s` treats findings as errors. The Xcode toolchain reports this swift-format as version `main`. There is no separate pin. The check does not rewrite files.
3. **Package.** In `Packages/SparkGridCore`: `swift build -c release`, then `swift test`.
4. **App builds.** Release `xcodebuild` of schemes `Spark Grid` and `Spark Grid Quick Look`, derived data `/tmp/spark-grid-ci-app` and `/tmp/spark-grid-ci-ql`, deleted when the stage ends. `CODE_SIGNING_ALLOWED=NO` only skips the signing identity. It does not change the deployment target or the Swift language mode. On a hosted runner (`CI` is set) whose `xcodebuild -version` major is below 27, this stage skips and says so. The deployment target stays macOS 14.0. Swift stays language mode 5.0. This machine has Xcode 27, so the stage runs here.
5. **Layers.** `scripts/check-layers.sh`. It fails if a target below `Rendering` imports AppKit, SwiftUI, Cocoa, or UIKit, or references `NSView`, `NSColor`, or `NSFont`, or if `Package.swift` depends on an equal or higher layer.
6. **Privacy and assets.** `scripts/check-privacy.sh`, then `scripts/check-assets.sh`. Privacy rules are in the section above. Assets fail while `ATTRIBUTION.md` is missing.
7. **Ledger.** `scripts/check-ledger.sh` runs the package test target `AnswerCheck`. That target is W5. Until it exists, the stage fails.
8. **KPI.** `scripts/check-kpi.sh` runs only when `SPARK_GRID_CORPUS` is set and this is not hosted CI. It skips when `CI` or `SPARK_GRID_CI` is set, and when the corpus variable is unset. If the corpus is set on a local machine and `AnswerCheck` is missing, the stage fails.
9. **Fuzz.** `scripts/check-fuzz.sh` runs the package test target `CommandFuzz`. That target is W5. Until it exists, the stage fails.

Layers, lowest first. Each target depends only on layers below it:

`GridCore`, `NumberFormat`, `Formula`, `Functions`, `Model`, `Calc`, `FileFormats`, `Engine`, `Rendering`.

The app and Quick Look depend on the package and `import SparkGridCore`. New engine code goes in the package, not the app target. `SpreadsheetDocumentStore` and `SpreadsheetViewModel` still live in the app because they present panels, pasteboard data, and windows. W7 moves commands behind a Foundation engine API. Until then, new view code reads engine state and does not mutate the model except through the existing view-model methods. The command registry itself is W7.

`.github/workflows/ci.yml` runs `scripts/ci.sh` on pushes and pull requests, on a `macos-15` runner. GitHub sets `CI`, so the KPI stage skips. If that runner's Xcode is older than 27, the app-build stage skips and the other stages still run. Do not lower the deployment target or the Swift settings so an older runner can compile.

Enable the fast hook once per clone:

```bash
git config core.hooksPath .githooks
```

`.githooks/pre-commit` runs lint, format, layers, privacy, and a debug `swift build` plus `swift test`. It does not run the Release app builds, the asset check, the ledger check, or fuzz. The hook is in the repo. This clone does not set `core.hooksPath` yet, because the gate fails and the hook would reject every commit on every branch until the gate is clean.

## Measuring

Follow `.cursor/rules/performance.mdc`. Release timings are the only timings that count. Debug numbers do not.

Paths to time, on the KPI file and on at least one other large workbook:

1. Open, from load through the first painted grid.
2. The unsaved-changes check.
3. First screen of each sheet.
4. One cell edit, through commit and the SwiftUI sync.
5. A tab switch.
6. Save and autosave.
7. Scrolling: the worst single screen.

Launch the existing harness with `SPARK_GRID_BENCHMARK=1`. The reference file is `SPARK_GRID_BENCHMARK_REFERENCE`. The second workbook is `SPARK_GRID_BENCHMARK_OTHER`, or the synthetic ledger from `scripts/generate_ledger_workbook.py` written to `/tmp`. Logs go to `SPARK_GRID_BENCHMARK_LOG` (default `/tmp/spark-grid-phase0-baseline.txt`). Do not point logs or answer files at a tracked path.

`BugBashRunner` is a debug harness. Nothing the shipping app needs may live only there. `recalculateEntireWorkbook` is not an app path. Do not report it as a user-facing win.

Until the W5 answer check exists, the scalar `FormulaEvaluator` is the answer check described in the performance rules. `YTD Summary!R5` in the KPI file is a malformed formula. A parse error is the correct result. Do not special-case that cell in engine code. W5 replaces the scalar self-check with a comparison against saved results.

The latest Release numbers are in `docs/STATUS.md`.

## Running and looking at the app

Requirements: macOS 14 or later, Xcode 27 or later recommended. Marketing version and build number are in the Xcode project. The app bundle id is `com.sparkbysam.SparkGrid`. Quick Look is `com.sparkbysam.SparkGrid.QuickLook`.

```bash
open "Spark Grid.xcodeproj"
```

Release build, own derived data, no signing when a local build only needs to run:

```bash
xcodebuild -scheme "Spark Grid" -configuration Release \
  -destination 'platform=macOS' \
  -derivedDataPath /tmp/spark-grid-dd \
  CODE_SIGNING_ALLOWED=NO build
```

Quick Look uses the scheme `Spark Grid Quick Look`.

There is no `spark-grid-cli` yet. That is W6. Until then, formula and file checks go through the app's benchmark launch or through package tests once `Packages/SparkGridCore` exists.

W6 commands, once they exist: `eval`, `cat`, `recalc`, `check`, `bench`, and `run`.

## When to ask the user

Do not stop to ask about anything this file, `docs/STATUS.md`, or the current task already decides.

Always ask Sam first before:

- uploading a build to App Store Connect
- pushing to `main` or rewriting git history
- deleting user data
- adding a third-party dependency
- reusing code from another project
- changing file-format compatibility
- loosening a gate
- any outward action, such as publishing, posting, or emailing
